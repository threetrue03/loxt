# LOXT 2.7.0 검토: 파일 유형·선택·데이터·비동기 동작

검토일: 2026-10-09. 실제 검토 대상은 `package.json`의 **2.6.0**이다. 이 문서는 다음 버전의 조사 자료이며 앱 버전을 변경하지 않았다. 기존 앱 코드, 설치 파일, 사이트, 사용자 기록·설정·모델을 수정하지 않았다.

## 핵심 결과

1. 여러 항목을 끌 때 `N개 녹음`이 고정 출력되는 원인을 확인했다. 폴더·메모·그리기·PDF·스크립트가 포함돼도 유형을 구분하지 않는다.
2. **요약 응답을 두 번 요약하면 전체 문장 수가 8로 바뀌어 더 읽기가 사라진다.** 실제 web RPC에서도 12문장 기록의 문장 수가 8로 반환되지만 상세 조회는 12문장을 유지했다. 또한 Live 오른쪽 폴더 탭의 더 읽기가 Work 보관함을 조회하는 잠재 경로가 존재한다.
3. 여러 종류의 항목과 폴더를 함께 이동·삭제하는 관리 계층 자체는 정상이다. 예전처럼 우클릭한 하나만 처리하는 버그를 현재 코드에서 다시 발견하지 않았다.
4. 폴더 삭제 후 휴지통의 ‘복구’는 기록을 내 보관함 루트로 돌려놓으며 원래 폴더 구조를 복구하지 않는다. 같은 세션의 관리 실행 취소는 폴더 구조까지 복구한다. 본문 손실과 구분해야 하는 구조·예측 가능성 문제다.
5. 드래그 문구만 바꾸면 파일 분류 불일치가 남는다. 메뉴·접근성 이름·목록의 그리기 표시도 같은 유형 판정으로 통일하는 편이 안전하다.

### B01: 실제 파일 분류와 권장 문구

현재 별도 파일로 저장되는 **메모를 빠뜨리지 말아야 한다**. 사용자가 열거한 녹음·스크립트·그리기·PDF·폴더 외에 메모도 실제 기능이다.

| 저장 상태 | 실제 식별 기준 | 표시 권장 |
|---|---|---|
| 일반 녹음 | 기본 기록; 오디오 존재 | 녹음 |
| 변환 완료 녹음 | 기본 기록, `done`, 오디오 존재 | 녹음·스크립트 또는 녹음(스크립트 포함) |
| 스크립트만 남은 기록 | `audioMissing` | 스크립트 |
| 분리된 원본 오디오 | `kind==='audio'` | 녹음 원본 |
| 독립 메모 | `kind==='memo'` | 메모 |
| 그리기 | `kind==='pdf' && documentType==='drawing'` | 그리기 |
| 가져온 PDF | `kind==='pdf'` 및 그리기 아님 | PDF |
| 폴더 | 선택 키 `folder:<path>` | 폴더 |

모두 같은 유형이면 `3개 PDF`, 혼합이면 `4개 항목`처럼 표시한다. 필요하면 보조 줄에 `폴더 1 · PDF 2 · 메모 1`을 표시한다. 변환 전·후를 임의로 별도 ID의 파일처럼 세면 안 된다. 원본을 분리해 휴지통으로 보낸 경우에만 실제 오디오 항목이 별도로 존재한다. 폴더 항목에도 유형을 전달하고 선택 ID에서 실제 기록을 조회해 분류한다.

### B02: 재현·기대 동작·원인

1. Live 보관함에 스크립트 12줄짜리 기록을 만든다.
2. 오른쪽 패널에서 Live 폴더 탭을 연다.
3. 카드 미리보기를 내려 ‘스크립트 더 보기’를 누른다.
4. 기대: 해당 Live 기록의 나머지 줄 표시.
5. 코드의 실제 조회 경로: `[data-workspace]` 조상을 찾는다. 오른쪽 패널은 Work/Live 메인 래퍼의 형제가 되어 이 속성이 없다. 그러면 `||'work'`가 적용된다.

검증용 별도 Work/Live 보관함에서 실제 `getFullNote` 함수를 호출했다. 같은 Live ID를 Work로 요청하면 `문서를 찾지 못했습니다.`, Live로 요청하면 12줄을 정상 반환했다. 이는 데이터가 Work로 이동한 문제가 아니라 **조회 모드가 잘못 선택되는 문제**다. 기본 메인 Live 화면은 `data-workspace='live'` 래퍼 안에 있어 동일한 오류를 일반화하면 안 된다. 주 담당의 실제 UI에서는 B08 때문에 더 읽기 버튼 자체가 나타나지 않아 이 클릭 경로를 직접 실행하지 못했다. B08 수정 후 B02를 다시 검증해야 한다.

권장 수정은 모드를 props로 전달하는 것이다. DOM 조상 선택자만 다른 속성으로 바꾸는 방법도 가능하지만, 조회에 필요한 정보를 레이아웃에 의존시키는 위험이 남는다. 변경 후 메인/오른쪽 패널 × Work/Live × 카드/작은 카드의 8줄 초과 미리보기를 확인해야 한다.

### B07: 취소 후 클릭 억제 상태

주 담당이 별도 Electron UI에서 혼합 항목 Ctrl+A → 카드 길게 눌러 드래그 → Esc → 마우스 버튼 놓기 → 메모 카드 1회 클릭을 실행했을 때 카드가 열리지 않고 보관함에 남는 현상을 재현했다. **두 번째 클릭에서는 정상적으로 열렸다.** `cancel()`은 gesture를 null로 만들지만 `suppress.current`를 지우지 않는다. 이때 원래 gesture의 `up()`은 즉시 반환하므로 억제 플래그를 해제하는 0ms timer도 실행되지 않는다. 이후 첫 클릭은 capture 단계에서 취소될 수 있다. 영구적으로 클릭이 막히는 현상이 아니라 취소 후 첫 클릭 소실이다.

`cancel()`에서 무조건 플래그를 즉시 지우면 정상 드래그를 놓을 때 합성 클릭이 카드를 여는 회귀가 발생할 수 있다. Esc/포인터 취소/범위 변경일 때 해제하고 정상 드롭 직후에는 해당 클릭만 억제하도록 종료 사유를 나눠야 한다. 영역 선택 취소·카드 드래그 취소·창 밖 포인터 취소·페이지 변경과 정상 드롭 후 카드가 저절로 열리지 않는 것을 함께 확인한다.

### B03: 폴더 복구 정책

예시 구조 `묶음/하위`에 스크립트 기록을 넣고 폴더 전체를 휴지통으로 옮긴 뒤 기록을 복구했다. `note.folder === ''`로 복구되고 폴더 목록에는 원래 경로가 남지 않았다. 같은 관리 세션에서 `undo`하면 폴더와 경로가 모두 복원됐다.

현재 삭제 확인 문구는 ‘N개 항목과 하위 기록을 휴지통으로 이동’이므로 폴더까지 나중에 복구할 수 있다고 받아들이기 쉽다. 데이터 내용은 유지되지만 **폴더 조직 정보는 일반 복구로 되살아나지 않는다**. 폴더 휴지통을 도입하면 동명 폴더 충돌, 상위 폴더 일부만 복원, 이동 후 복원, 기존 detached audio 연결을 함께 검증해야 한다. 기존 녹음 ID·본문·첨부 파일을 새 ID로 복사하는 방식은 피한다.

### B08: 요약의 반복 적용

`summary(note)`는 첫 8개의 문장만 포함하면서 전체 수를 `note.segments.length`로 계산한다. 첫 호출에서는 12문장이 `segments.length=8, segmentCount=12`가 된다. 이미 요약된 객체를 다시 호출하면 `segmentCount=8`로 덮어쓴다.

데스크톱 `library:list`와 Live `workspace:library`의 list는 `listSummary()`를 반환하며 공통 `handle()`이 다시 `lightResult()`를 적용한다. 웹도 `library.list`에서 `listSummary()`를 반환한 후 `rpc` wrapper가 `lightResult()`를 적용한다. 실제 예시 web RPC는 `segmentCount=8`을 반환했다. `library.detail`은 12개의 전체 문장을 반환하므로 원문 데이터 손실로 보고하면 안 된다.

주 담당의 별도 앱에서는 24문장의 Live 카드가 처음 8문장만 표시하며 `.preview-more` 버튼이 없는 것을 확인했다. 결과적으로 B02의 잘못된 모드 경로가 가려진다. 원문을 불러오는 상세 화면과 경량 카드 목록을 모두 검증해야 한다. 요약 객체를 구분하는 `_summary`와 유효한 `segmentCount`를 보존하는 방식이 작은 수정이며, 필요할 때마다 원문 전체를 목록에 싣는 방식은 기존 메모리·동기화 최적화를 되돌린다.

## 정상으로 확인한 부분

- 선택된 항목에서 우클릭하면 `menu.ids`에 전체 선택 ID를 보존한다. 선택 밖의 항목을 우클릭하면 그 항목만 대상으로 한다 (`LibraryView.jsx:84,124`).
- 혼합 선택의 폴더와 기록 ID는 `split`에서 구분하고 관리 backend가 폴더 하위 항목까지 처리한다.
- 관리 작업은 보관함 직렬 큐와 durable journal을 사용한다. 중단 후 폴더 변경 재생과 원본 보존 테스트가 통과했다.
- 실행 취소는 다른 작업으로 경로·삭제 상태가 달라진 경우 거부한다. 이를 덮어써 되돌리지는 않는다.
- 오디오만 휴지통으로 보내도 스크립트·메모·기록 ID가 유지되며 별도 원본 복구·영구 삭제 테스트가 통과했다.
- 메모/PDF 저장의 revision 충돌 방지, 손상된 인덱스/본문 복구, 그리기 페이지 identity와 export 회귀 테스트가 통과했다.
- 모델 역할의 Work/Live 분리, 설정 저장 실패 롤백, 캐시 정책, 업데이트 취소 시 기존 모델 유지와 설치 중단 복구 테스트가 통과했다. 이번 조사에서는 실제 모델 재다운로드나 GPU 실행을 반복하지 않았다.

## 확인 범위의 한계

이 분담은 데이터·코드·기존 테스트를 담당했고 실제 Electron UI는 주 담당이 별도 프로필로 검증한다. 실제 마이크/루프백, iPad Safari, 대용량 사용자 PDF, 물리 장치 연결 해제, 네트워크 손실, 디스크 전체 부족은 이번 분담에서 검증하지 않았다. 가짜 오디오 바이트와 예시 스크립트는 관리 흐름 검증용이며 변환 성공 증거가 아니다.

향후 구현 순서는 B08/B02의 요약·조회 모드 수정, B01+B04+B05의 공통 유형 판정, B07의 취소 상태 수정, B06의 메뉴 일관성, B03의 복구 정책 결정 순을 권장한다. B03 구조 변경은 작은 문구 수정과 묶어 조용히 진행하지 말고 명시적 설계 범위로 다룬다.
