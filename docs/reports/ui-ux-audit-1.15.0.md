# LOXT 1.15.0 UI·UX 조사 및 수정 요구사항 통합 보고서

- 작성일: 2026-10-08
- 기준 버전: `package.json` 및 조사에 사용한 Windows 패키징 앱 1.15.0
- 범위: 최근 녹음 버튼·테마 조사와 반응형·내보내기·모달 조사, 이어서 요청한 수정 사항
- 상태: **조사 및 요구사항 정리 완료 / 이 보고서의 수정 사항은 미구현**
- 기존 방향: SUIT 글꼴, 차콜 색상, 다크·라이트 테마, LOXT 로고와 기존 기능을 유지한다.

이 문서는 최근 두 조사 결과를 통합한 것이다. 과거 A01–A16·S01–S29 보고서 전체를 다시 검증한 보고서는 아니다. 앱 코드·설정·설치 프로그램·소개 사이트·실제 사용자 데이터는 이번 문서 작성 과정에서 변경하지 않았다.

## 1. 가장 중요한 문제 5개

1. **녹음 버튼의 호버 가독성:** Work의 녹음 중·일시정지·변환 대기 버튼에 마우스를 올리면 글자 대비가 다크 1.11:1, 라이트 1.28:1로 떨어진다.
2. **좁은 폴더 화면의 조작 버튼 잘림:** 오른쪽 패널을 열거나 넓히면 새로 추가하기와 보기 전환 버튼이 메인 영역 밖으로 나간다. 180개 화면 조합 중 36개에서 버튼 경계 넘침을 측정했다.
3. **좁은 설정 화면의 가독성:** 모델 이름이 한 글자씩 세로로 갈라지고 설정 메뉴가 잘린다. 고정 액션 열이 모델 이름 공간을 지나치게 차지한다.
4. **녹음 중단 후 버튼 구성:** 사용자가 요청한 구성은 왼쪽 버리기·오른쪽 단독 변환하기다. 현재 구성에는 녹음 계속과 비활성 장치 화살표가 남고 버리기는 창 안에 있다.
5. **모달 배경 처리 누락:** 모달보다 상단 바의 레이어가 높아 로고와 상단 버튼이 흐려지지 않는다. 헤더 클릭 가능 문제로 재현된 것은 아니며 시각적 레이어 문제다.

추가로 스크립트 제목 잘림, 내보내기 크기 불일치, 분할 버튼 포커스 외곽과 변환 버튼 색상의 의미를 정리할 필요가 있다.

## 2. 조사 방법과 검증 범위

### 녹음 버튼 조사

- 현재 패키징 앱, 1440×900 창, 비공개 테스트 프로필과 무음 가상 마이크를 사용했다.
- 실제 테마 API로 다크·라이트를 전환했다.
- Work 시작 전·녹음 중·일시정지·변환 대기 상태에서 기본·호버·실제 Tab 키보드 포커스를 확인했다.
- computed CSS 색상으로 대비를 계산하고 24개 버튼 캡처를 남겼다.
- 실제 마이크 음성이나 GPU 추론 성공을 검증한 작업은 아니다.

### 화면·반응형 조사

**Work·Live × 다크·라이트 × 9개 화면 × 5개 조건 = 180개 조합**을 조사했다. 창 크기 변경, 오른쪽 패널의 실제 드래그, 앱 확대, 화면 탐색, 네이티브 캡처와 DOM/CSS 크기 측정을 사용했다.

| 구분 | 조건 |
|---|---|
| 화면 | 홈, 폴더 목록, 카드, 작은 카드, 스크립트, 스크립트+메모, 독립 메모, 설정 일반, 모델 보관함 |
| 창·패널 | 1440px 창 / 860px 창 / 860px+패널 / 1440px+패널 드래그로 메인 폭 축소 / 1440px+앱 확대 150%+패널 |
| 별도 확인 | 라이트 YouTube 모달, 스크립트 내보내기 크기 |
| 데이터 | 별도 예시 보관함·메모·녹음. 실제 사용자 보관함은 변경하지 않음 |

앱 확대 150%는 Electron 확대 비율이며 **Windows 전체 화면 DPI 변경 검증과 다르다**. 경계 넘침 36건은 모든 시각적 문제의 총수가 아니다. 모델 이름 줄바꿈·제목 잘림 등은 캡처로 별도 확인했다.

## 4. 중요한 항목의 상세 근거와 해결 방향

### U01·U08·U09 — 녹음 버튼 테마와 포커스

**위치:** `src/panel.css:2,7`, `src/styles.css:7,32`, `src/RecordingPage.jsx:254`.

**재현:** Work 녹음을 시작하고 녹음 중·일시정지·중단 후 변환 대기 상태에서 버튼 위에 마우스를 올린다. 다크·라이트 각각 반복하고 Tab으로 주 버튼과 장치 화살표를 이동한다.

| 상태 | 다크 기본 / 호버 / 포커스 | 라이트 기본 / 호버 / 포커스 |
|---|---|---|
| 시작 전 | 13.16 / 11.78 / 13.16 | 15.24 / 11.94 / 15.24 |
| 녹음 중·일시정지·변환 대기 | 7.65 / **1.11** / 7.65 | 5.47 / **1.28** / 5.47 |

수치는 대비 비율 `:1`이다. 기본·키보드 포커스만으로는 글자 대비가 떨어지지 않았다. 사용자 캡처처럼 포커스와 호버가 함께 적용되면 호버 색상 충돌이 발생할 수 있다.

부모 그룹에서 글자색을 상속하는 상태에서 자식 호버 배경만 강제 변경한다. 다크는 `#30302f` 배경과 `#372421` 글자, 라이트는 `#E1E5DD` 배경과 흰색 글자의 조합이 된다.

**기대:** 기본·호버·포커스에서 문구가 읽히며 키보드 포커스가 보인다. **권장:** 상태별 색상 쌍과 호버 규칙을 함께 정리하고, 분할 버튼을 유지하는 상태에서는 그룹 외곽과 현재 포커스 대상을 모두 구분한다. 포커스 제거로 해결하지 않는다. Live도 같은 CSS를 쓰지만 실제 실행 중 호버 검증은 아직 하지 않았다.

참고 기준: [WCAG 일반 텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)의 4.5:1. 비활성 버튼에는 별도 예외가 있으므로 활성 버튼과 구분해 평가한다.

### U02·U03·U05 — 좁은 화면·패널 반응형

**위치:** `src/panel.css:1,2,8,9`, `src/styles.css:32,230`, `src/NoteDetail.jsx`.

**재현:** 폴더에서 오른쪽 패널을 열고 구분선을 왼쪽으로 드래그한다. 목록·카드·작은 카드에서 추가·보기 버튼 경계를 확인한다. 설정 모델 보관함과 스크립트+메모로 이동해 이름·제목을 확인한다. 양 테마와 Work·Live에서 반복한다.

**실제:** 폴더 도구 모음이 메인 경계를 넘고, 모델 이름이 세로로 분절되며, 제목 끝이 잘린다. 좁은 설정의 `minmax(0,1fr) 170px` 열 구성은 이름에 필요한 너비를 소진한다.

**기대:** 창 전체 너비가 아니라 사이드바·오른쪽 패널을 제외한 실제 콘텐츠 폭에서 읽고 조작할 수 있어야 한다.

**권장:** 도구 모음을 줄바꿈하거나 행으로 재배치하고 설정 행의 액션 열을 좁은 폭에서 재구성한다. 제목은 편집 시 입력 접근성을 유지하고 비편집 시 명확한 말줄임·줄바꿈을 사용한다. 무조건 글꼴을 줄이거나 overflow만 숨겨 필수 조작을 없애지 않는다. 스크립트·메모 내용의 좁은 폭 세로 배치는 조사 화면에서 동작했으므로 제목과 도구 모음 문제를 구분한다.

**주의:** 레이아웃 수정 후 우클릭·드롭다운·선택·드래그 이동과 리사이저 최소 폭을 다시 검증해야 한다.

### U04 — 중단 후 버리기·변환하기

**위치:** `src/RecordingPage.jsx:194,254,259`, `src/ConversionDialog.jsx`.

최신 요청의 흐름은 다음과 같다.

```text
녹음 중      [ 일시정지 ] [ 녹음 중단 ]
중단 후      [ 버리기   ] [ 변환하기  ]
변환 클릭    → 폴더·모델 선택 창 → 변환하기
창 닫기      → 중단 후 버튼 구성 유지
```

- 변환하기는 장치 선택 화살표 없는 단독 버튼으로 만든다.
- 중단 후 왼쪽 버튼을 버리기로 바꾸고, 선택 창 내부의 버리기를 제거한다.
- 버리기는 기존 위험 동작 스타일, 변환하기는 기존 일반 실행 스타일을 따른다.
- 중단 전 일반 일시정지·재개 기능과 중단 후 변환 대기 상태를 구분한다.

현재 중단 동작은 MediaRecorder를 일시정지하고 변환 확인 시 저장을 마무리하는 구조다. 버튼 이름만 바꾸지 말고 저장·버리기·장치 연결 해제·저장 실패 복구·페이지 이동·메모 저장 상태도 함께 확인해야 한다. 새 요청의 중단 이후에는 녹음 계속 버튼을 남기지 않는다.

### U06 — 스크립트 내보내기 크기

**위치:** `src/NoteDetail.jsx`의 `script-export-menu`, `src/styles.css:32`. 메모의 별도 기준은 `src/memo.css:5`.

| 버튼 | 높이 | 글꼴 | 패딩 |
|---|---:|---:|---|
| 스크립트 내보내기 | 39px | 12px | 8px 12px |
| 전체 복사·메모 | 약 26.1px | 11px | 4px 8px |

스크립트 도구 모음 안의 내보내기 높이·아이콘·패딩을 인접 버튼에 맞춘다. **TXT/PDF 선택용 드롭다운 화살표는 유지**한다. 변환하기의 화살표 제거 요청과 혼동하지 않는다. 메모 도구 모음은 기존 32px 기준이 있으므로 전역 메뉴 크기를 일괄 축소하지 않는다.

### U07 — 모달과 상단 바 레이어

**위치:** `src/styles.css:14,51`, `src/Modal.jsx:11–26`.

**재현:** 라이트 테마에서 YouTube 불러오기 창을 열어 로고·상단 바와 나머지 배경을 비교한다.

**실제:** overlay는 `z-index:5`, 앱 헤더는 `15`다. 로고가 차광·흐림 위로 나온다. 조사에서 헤더는 inert 상태였으므로 클릭 가능한 것으로 보고하지 않는다.

**권장:** 상단 바·로고·오른쪽 패널을 포함한 앱 배경에 일관된 차광·흐림을 적용한다. Windows 네이티브 제목 표시줄은 앱 배경과 구분한다. 모달 내부 드롭다운의 레이어, 키보드 포커스 유지·복귀, 배경 조작 차단과 네이티브 브라우저 가림 처리를 함께 검증한다.

## 5. 수정 후 검증 기준

- 두 테마에서 Work·Live의 시작 전/녹음/일시정지/중단 후/로딩 상태별 기본·호버·포커스·비활성 표시를 확인한다.
- Work 중단 후에는 버리기·단독 변환하기가 보이고, 창 내부 버리기는 없어야 한다. 창 닫기·페이지 이동에도 상태를 보존한다.
- 변환 확인은 한 번만 처리하고 버리기·저장 실패·장치 연결 해제 시 녹음과 메모 데이터의 동작을 확인한다.
- 좁은 창과 오른쪽 패널 드래그에서 제목·경로·모델 이름·조작 버튼이 잘리지 않는지 실제 앱 캡처로 확인한다.
- 스크립트·메모 리사이저, 목록/카드/작은 카드, 사이드바 열기·닫기, 메뉴·우클릭·선택·드래그 기능을 유지한다.
- 실제 Windows 화면 배율도 별도로 검증하고 앱 확대 결과와 구분해 기록한다.
- 모달이 배경 전체를 가리고, 키보드 포커스가 내부에 유지되며 닫은 뒤 적절히 복귀하는지 확인한다.

## 6. 권장 진행 순서

### 바로 해결

U01 버튼 호버 가독성, U02 폴더 조작 잘림, U03 모델 이름·설정 탐색 문제.

### 같은 UI 수정에서 묶어 해결

U04 중단 후 버튼 흐름, U05 제목 표시, U06 내보내기 크기, U07 모달 레이어, U08 키보드 포커스, U09 상태별 버튼 의미. 함께 검증해 상태·테마별 스타일 충돌을 줄인다.

### 후속 검증

실제 Windows DPI, 실제 Live 녹음 중 반응형·버튼 상태, 모든 메뉴·오류·휴지통 상태, 브라우저 사이트별 레이아웃. GPU 추론 속도·정확도와 음소거 시 시스템 소리 캡처는 이 UI 조사로 검증된 항목이 아니다.

### 유지해도 되는 부분

기존 SUIT·색상·로고 방향, 조사한 시작 전 버튼의 대비, 스크립트 내보내기 형식 선택, 좁은 스크립트+메모 내용의 세로 배치, 기존 모달 포커스 보호 의도. 문제가 없는 부분을 새 디자인으로 교체할 필요는 없다.
