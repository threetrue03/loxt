# LOXT 1.15.0 검증

## 승인 범위

추가 승인에 따라 같은 1.15.0 버전에서 Work 녹음 중단과 변환 선택 창 열기를 분리했다. 녹음 중단은 일시정지하고 버튼을 변환하기로 바꾼다. 사용자가 변환하기를 눌러야 선택 창이 열리며, 닫기·페이지/워크스페이스 이동·녹음 계속은 기존 녹음과 메모를 유지한다. PDF 뷰어·필기 및 iPad/iPhone 연동은 구현하지 않았다.

PDF·폴더 ZIP 내보내기, 오른쪽 패널 열기와 Ctrl+W, 현재 경로의 사이드바 폴더 생성, Work 녹음 메모, 메모 UI 단순화와 Escape 입력 규칙 취소, Work 화자 분석 제외를 구현했다. 앞서 코드만 수정했던 텍스트 선택 제한·Ctrl+T·Live 안내 문구 제거도 이번 설치 파일에 포함한다.

## 구현과 데이터 보존

- 메모 HTML·Markdown 직렬화 결과를 기다린 후 IPC로 전달한다. PDF는 SUIT와 로컬 이미지를 포함한 문서의 로딩을 기다리고 출력하며, 임시 결과가 완성된 뒤 목적지를 교체한다.
- ZIP은 스트리밍하고 읽은 스냅샷을 내보낸다. 하위·빈 폴더, 원본 음성, 스크립트 TXT, 메모 Markdown과 참조된 첨부파일을 포함한다. 휴지통 및 다른 폴더는 제외한다. 해당 폴더에 녹음 세션이 있으면 종료하도록 안내한다. 생성 실패 시 기존 목적지 파일을 유지한다.
- Work 메모는 활성 녹음 ID에 연결한다. 자동 저장하고 원본을 확정하기 전에 메모 저장을 기다린다. 사용자 기록의 이동·변환·삭제 로직을 교체하지 않았다.
- 새 Work 변환에는 화자 분석을 호출하지 않고, Live 변환은 기존 분석을 유지한다. 이전 저장된 화자 표시를 일괄 제거하지 않는다.

## 검증 결과

- 추가 변경의 source 및 최종 패키징 앱 녹음 UI 검증 통과: 중단 시 창/추론 요청 없음, 일시정지 동안 타이머 유지, 명시적 변환하기로 창 열기, 창 닫기와 Work·Live 전환 후 상태 유지, 녹음 재개와 일반 일시정지 구분, 변환 확인 시 원본 확정·메모 보존·변환 요청 정확히 1회, 버리기 후 추가 요청 없음. `test-results/recording-review-1.15.0/source.json` 및 `packaged.json`. 별도 프로필, 무음 가상 입력 및 추론 요청 대체를 사용했다.

- 회귀 테스트 74개 통과: `test-results/release-1.15.0.log`.
- ZIP 내용 검증 통과: 하위 폴더·원본 바이트·한글 스크립트·Markdown 체크 목록·첨부파일, 휴지통 제외, 활성 녹음 거절, 실패 후 기존 파일 유지와 임시 ZIP 정리.
- 메모 UI 테스트 통과: 저장 실패 주입과 재시도, 페이지 이동, 블록 메뉴·서식·수식·첨부파일·검색, Markdown·HTML·PDF 실제 저장, 앱 종료 및 현재 저장 위치에서 재실행 확인. 파일 선택기와 실패 주입은 private 테스트 앱에서만 대체했다.
- 최종 패키지의 워크플로 UI 검증 통과: 실제 폴더 ZIP 버튼과 IPC, 스크립트 PDF 출력, Work·Live 현재 폴더 아래 사이드바 생성, Escape로 체크 목록·제목 입력 기호 복원, Work 가상 마이크 녹음 중 메모 작성·페이지 이동·녹음 종료·앱 재실행 후 메모 보존. 출력은 실행마다 새로운 디렉터리에 생성해 이전 파일로 성공을 판단하지 않았다. `test-results/workflow-1.15.0/results.json`.
- PDF: 한글·표·체크 목록·토글·수식이 포함된 메모와 60문장의 4페이지 스크립트를 실제 출력했다. pypdf로 한글 텍스트를 확인하고 pypdfium2로 모든 페이지를 렌더링해 잘림 여부를 점검했다. `test-results/pdf-1.15.0/`.
- source 및 최종 패키지의 패널 UI 검증 통과: Ctrl+T, Ctrl+W를 앱과 native 브라우저 포커스에서 확인. 패널 재열기 시 탭 개수 유지, 독립 경로·검색, 세션 유지, 보관함 이동·실행 취소, 860px 창의 수평 넘침 없음. `test-results/panel-1.15.0/results.json`.

초기 테스트 실패에는 sandbox의 임시 파일 교체·하드링크 권한, 이전 Work 화자 분석 기대값, 홈 생성 메뉴·마이그레이션 이전 저장 경로를 참조하는 오래된 검증, 테스트의 마이크 권한 창 응답 및 비동기 대기 문제가 포함되었다. 해당 원인을 구분해 검증 코드와 테스트 실행 환경을 바로잡았다. 추가 검증 중 Playwright 화면 캡처가 시간 초과되어 앱의 capturePage로 교체했고, 사이트 촬영의 첫 창 대기 시간 초과가 반복되어 촬영 전용 프로필을 현재 LOXT/work-library·live-library 구조로 직접 구성했다. 이후 27장 촬영과 사이트 검증을 통과했다. 앱의 보관함 이전 코드는 바꾸지 않았다. 성공 여부를 화면의 예시 스크립트로 판단하지 않았다.

## 검증 한계

실제 마이크, 스피커·헤드셋, Windows 음소거/볼륨 0 및 실제 GPU 추론은 이번 변경에서 다시 검증하지 않았다. 녹음 검증은 가상 음성 입력, 화자 분석 분기 검증은 모의 엔진 결과를 사용했다. Live 성능 개선과 음소거 상태의 시스템 소리 캡처 변경은 포함하지 않는다.

사용자가 보고한 음소거 문제의 현재 입력 경로는 `python/system_audio.py`의 SoundCard/WASAPI 기본 출력 장치 루프백이다. Microsoft의 출력 장치에 종속되지 않는 프로세스 루프백을 후속 후보로 검토할 수 있지만, 이 PC에서 음소거 상태 캡처 성공은 아직 확인하지 않았다. 사용자 출력 장치나 Windows 볼륨을 임의로 변경하지 않았다.

## 릴리스 준비

앱·설치 파일·사이트·README 버전은 1.15.0이다. 최종 Windows 설치 파일의 SHA-256은 `6194b7469a709667933d6117eb933f754ac6f701f6a3a208610b836f196ae8fc`이다. 패키징 앱을 별도 예시 프로필로 27장 촬영했으며 소개용 문장·Live 이벤트는 음성 인식 증거가 아니다. 사이트 390·768·1440px 검사, 테마·이미지·FAQ·다운로드 URL 검증을 통과하고 `landing/loxt-site-v1.15.0.zip`을 생성했다.

Git commit/push·릴리스 업로드·Cloudflare Production 배포는 실행하지 않았다. 2026-10-08 공개 릴리스 태그와 설치 파일 URL의 HEAD 요청은 둘 다 404였다. 게시 전 릴리스 자산 업로드가 필요하다.
