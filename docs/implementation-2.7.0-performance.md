# LOXT 2.7.0 — V17·V19·V20·V21 구현·검증

2026-10-09 구현, 2026-10-10 최종 검토. 사용자 보관함·녹음·모델·설정에 쓰지 않고 별도 test-results 예시 데이터로 확인했다. 전체 릴리스 완료 여부는 통합 검증 기록이 우선한다.

## 구현

- **V17:** 메모 미리보기는 목표 문자 수에 도달하면 배열·표·자식 순회를 종료한다. 서버에서 검증 후 깊게 동결한 블록의 개수·깊이·UTF-8 크기를 재사용하고 새로운 patch 블록은 형식·첨부/링크 URL·중첩을 다시 검증한다. 전체 10,000블록·5MB 한도, revision 충돌, journal checksum·fsync·checkpoint·손상 복구는 그대로 유지한다. 같은 검증을 journal replay에도 적용한다.
- 초안 생성은 500ms 병합/최대 1.5초 checkpoint로 조정했다. 본문 durable 저장 120ms 병합/최대 600ms checkpoint는 유지한다. 저장 실패·종료·최신 내용 조회에서는 즉시 초안을 보존한다.
- **V19:** 모델 검색 cache는 80개/16MiB 상한과 TTL 정리를 적용했다. 마지막 정상 `featured`와 진행 중·현재 요청 파일은 보호한다. 종료·재실행 뒤 cache 경로에서 관리 목록을 다시 읽는다. 목록 파일 전체를 매 요청 파싱하지 않고 작은 메타데이터 헤더와 같은 실행 안의 관리 목록을 사용한다. 정리 실패는 유효한 모델 정보나 모델 파일을 삭제하지 않는다.
- **V20:** adapter별 모델 snapshot·list request·이벤트 구독을 공유한다. 홈은 모델 정보 snapshot만 구독하고 스토어는 설치 진행률을 포함한 환경 snapshot을 구독한다. 커지는 스크립트/파형 데이터는 signature에서 제외한다. 마지막 구독자 종료 때 리스너를 해제하고 늦은 응답을 차단한다. 별도 adapter의 상태는 섞이지 않는다.
- **V21:** 메모·필기·전체 스크립트 각각 건수와 추정 보관 데이터 크기를 함께 제한한다. 원격은 종류별 16MiB, PC는 종류별 32MiB다. **이 수치는 전체 앱 RAM 상한이 아니며 정확한 heap 측정치도 아니다.** payload 변경 시 참조 기반 크기를 계산하고, active·dirty·saving·loading·pending 항목을 먼저 보존한다. 보호할 내용만으로 budget을 초과하면 해당 내용을 버리지 않는다. 필기는 undo/redo 보관 데이터도 계산에 포함한다.
- 스크립트 상세를 닫거나 다른 문서 유형으로 바꾸면 React의 이전 상세 본문 state도 비운다. 페이지를 떠난 뒤 늦게 도착한 응답은 기존 mounted guard로 반영하지 않는다.

## 검증

`scripts/performance-2.7.test.mjs` 새 8개와 기존 모델 스토어 8개 **16/16 통과**. 기존 메모·원격 동기화·PDF 관련 **17/17 통과**. 최초 WebSocket 실패는 sandbox의 `connect EACCES`였으며 예시 TEMP와 로컬 소켓 실행 권한으로 재검증했다. 앱 버그로 집계하지 않는다. JS syntax와 `git diff --check`도 통과했다.

테스트는 중첩·표·빈 텍스트 순서, 미리보기 뒤 불필요한 접근 금지, 새로운 악성 URL 거부, frozen 블록 변조 거부, 문서 전체 크기·개수 한도, durable 재시작과 invalid patch revision 보호, 바이트 LRU와 실제 활성 메모 초안 보존, 공유 요청·구독·정리·adapter 분리, TTL·개수·바이트 cache 한도와 오프라인 featured 보존을 확인한다.

## 같은 예시 데이터의 전후 측정

Node 22.17.0, Ryzen 7 4800H, RAM 약 15.36GiB, 프로젝트 OneDrive 안의 예시 경로. 함수 측정은 15회 중앙값, 실제 durable 저장은 10회. 이전 조사와 같은 블록/문자/수정 위치를 사용했다. OS cache와 디스크 상태를 통제하지 않았고 네트워크·실제 Safari 렌더 시간은 포함하지 않았다.

| 조건 | 변경 전 | 변경 후 |
|---|---:|---:|
| 100블록의 2,000자 미리보기 | 0.31ms | 0.05ms |
| 1,000블록의 2,000자 미리보기 | 1.19ms | 0.04ms |
| 10,000블록·4.20MB의 2,000자 미리보기 | 13.85ms | 0.09ms |
| 10,000블록 문서에서 한 블록 변경 검증 | 기존 전체 검증 27.31ms | 검증된 기존 블록 재사용 0.20ms |
| 1,000블록 실제 durable 한 블록 부분 저장 | 12.69ms | 7.79ms |

부분 저장의 최대 관측치는 **20.93ms → 23.49ms**로 오히려 높았다. 중앙값이 낮아졌다고 모든 저장의 지연·전체 동기화 시간이 보장돼 개선됐다고 표현하지 않는다. 처음 읽는 미검증 문서는 전체 검증·동결 비용이 필요하며 위 0.20ms는 **기존 문서가 검증된 patch 경로**의 수치다.

증거: `test-results/audit-2.7.0/performance/implementation-tests.log`, `document-regression.log`, `implementation-measurements.json`, `implementation-measure.mjs`. 기존 조사 `measurements.json`은 덮어쓰지 않고 보존했다.

## 남은 통합 검증

목차·검색·미리보기와 함께 실제 패키지 메모 저장·재실행, Work·Live·오른쪽 패널 동시 구독, 실제 모바일 문서 이동·복구·오프라인 전환은 주 담당의 UI/릴리스 검증에서 확인한다. 테스트 프로필의 합성 데이터는 음성 추론 성공 증거가 아니다.
