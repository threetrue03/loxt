## 1. 제품 목표와 확정 범위

### 1.1 기본 구조

LOXT 설치 사용자마다 **자기 PC가 자기 보관함과 변환을 담당하는 개인 서버**를 갖는다.

```text
사용자 A: A의 PC LOXT ← 같은 로컬 네트워크 → A의 아이패드·아이폰
사용자 B: B의 PC LOXT ← 같은 로컬 네트워크 → B의 아이패드·아이폰

PC 앱 화면 ── Electron 연결 ── 공통 보관함·변환 서비스
모바일 웹 ─── 인증된 HTTPS 연결 ── 같은 공통 서비스
```

- 운영자가 제공하는 공용 데이터 서버, 계정 서비스, 클라우드 보관함을 만들지 마.
- 사용자 A의 파일이 개발자 PC나 사용자 B의 보관함에 생기는 구조를 만들지 마.
- 모바일은 승인한 PC의 동일한 Work/Live 보관함에 접근한다. 기기마다 별도 공식 보관함을 복제하는 구조가 아니다.
- PC가 보관함의 기준 데이터를 관리한다. 모바일 임시 저장은 연결 복구·데이터 보호 용도로만 사용한다.
- 사용자에게 Node 설치, 터미널 명령, 직접 서버 실행을 요구하지 마. Windows 설치 파일에 필요한 실행 기능을 포함한다.
- 기존 데스크톱 사용은 모바일 연결 여부·네트워크·인증서와 무관하게 유지한다.

## 2. 기존 기능과 디자인 보호

- SUIT, 차콜 색상, 기존 다크·라이트 토큰, LOXT 로고, 메뉴·아이콘·테두리·라운드·간격을 유지한다.
- 기존 스타일을 읽고 확장한다. 새 디자인 시스템이나 전체 UI 교체를 하지 마.
- 사용자 녹음·스크립트·폴더·모델·메모·설정·첨부파일을 보존한다.
- 기존 `sorinote-desktop` 데이터 경로 등 호환용 이름을 임의로 바꾸지 마. 이번 목표 때문에 데이터 경로를 강제 이동하지 않는다.
- 기존 Work 대기열, Live GPU 조정, 페이지·워크스페이스 이동 중 PC 녹음, Work 녹음 중 메모를 유지한다.
- 기존 오른쪽 패널·폴더 탭·브라우저·Ctrl+T·Ctrl+W 동작을 PC에서 유지한다.
- 기존의 Work 화자 분석 제외, Live 화자 표시, 테마·모델·설정 기능을 임의로 변경하지 않는다.
- 웹뷰의 iframe이나 공개 소개 사이트 안에 개인 보관함을 끼워 넣는 방식으로 만들지 마. 개인 서버가 자체 웹 화면을 제공한다.

### 3.1 Work 녹음 중단 흐름

```text
시작 전     [ 녹음 시작 │ 장치 ▾ ]
녹음 중     [ 일시정지 ] [ 녹음 중단 ]
일시정지    [ 녹음 계속 ] [ 녹음 중단 ]
중단 후     [ 버리기 ] [ 변환하기 ]
변환 클릭   → 저장 폴더·모델 선택 창 → 변환하기
창 닫기     → 중단 후 화면 유지
```

- 중단 후에는 녹음 계속·장치 선택 화살표를 남기지 마. 일반 일시정지와 최종 중단을 구분한다.
- 중단 버튼 자체로 선택 창을 바로 열지 마.
- 최종 중단은 오디오 스트림을 정리하고, 메모를 안전하게 저장하며, 녹음 파일을 보존한 변환 대기 상태로 전환한다.
- 기존 저장 복구 구조를 확인해 중복 저장·중복 대기열 등록을 방지한다. 저장 실패 시 오디오 복구 가능성을 보존하고 재시도를 제공한다.
- 페이지 이동·창 닫기·앱 재실행 후 변환 대기 녹음을 복구할 수 있어야 한다. 저장하지 않은 녹음을 조용히 잃어버리지 마.
- 버리기는 기존 버리기 의미를 유지한다. 연관 메모 처리와 확인 동작은 기존 구현을 읽고 일관되게 유지한다.
- 변환 창 내부의 버리기는 제거한다. 변환 창 닫기는 녹음 삭제가 아니다.
- 새 녹음에서 선택하는 폴더는 기존 합의대로 최상위 사용자 폴더만 표시하고 시스템 루트는 폴더 항목으로 노출하지 않는다. 미지정은 내 보관함에 저장한다.
- 기존 기록 재변환은 기존 위치 보존 흐름을 유지한다.

### 3.2 반응형·버튼·모달

- 전체 창 너비 대신 사이드바·오른쪽 패널·메모 패널을 제외한 실제 콘텐츠 폭으로 재배치한다.
- 필수 조작을 단순히 overflow hidden으로 감추거나 글꼴을 무조건 작게 만들지 마.
- 제목 편집은 입력 내용에 접근할 수 있어야 하고 비편집 표시에서는 명확한 말줄임·줄바꿈을 사용한다.
- 스크립트 내보내기에는 TXT/PDF 드롭다운 화살표를 유지한다. 변환하기 화살표 제거와 혼동하지 마.
- 데스크톱 스크립트 도구 모음만 크기를 맞춘다. 모바일에는 터치 가능한 충분한 영역을 제공하며 약 26px 데스크톱 버튼 높이를 강제 복제하지 않는다.
- 모달 포커스 유지·닫은 뒤 복귀·배경 조작 차단을 검증한다. 네이티브 브라우저 영역도 기존 가림 처리를 유지한다.
- 활성 일반 텍스트 대비는 4.5:1 이상을 목표로 측정한다. 키보드 포커스는 제거하지 않는다.

## 4. PDF를 보관함 항목으로 추가

- PDF는 녹음·메모와 동등한 독립 항목이다. 모델 변환 대상 오디오로 분류하지 마.
- Work·Live의 사용자 폴더에서 `새로 추가하기 → PDF 불러오기`를 제공한다.
- 기존 홈에는 새로 추가하기·빈 공간 생성 메뉴를 되살리지 마. PDF 가져오기는 폴더·보관함 문맥에서 한다.
- PC 파일 선택·폴더 화면 파일 드롭, 모바일 파일 선택·업로드를 지원한다. OS 폴더를 상시 감시해 자동 수집하는 기능은 추가하지 않는다.
- 목록·카드·작은 카드·제목/내용 검색·이름 변경·폴더 이동·휴지통 복구·영구 삭제·폴더 ZIP에 PDF를 통합한다.
- 폴더 ZIP에는 PDF 원본과 버전 있는 필기 JSON을 포함한다. 필기 포함 PDF 내보내기는 별도 기능이다.
- PDF 카드에 불필요한 상태 배지를 더하지 마. 기존 카드 선택·드래그·우클릭 동작을 유지한다.
- PDF 항목을 눌러 메인에서 열고, 기존 오른쪽 폴더 탭에서도 같은 뷰어를 재사용한다. 같은 문서를 두 화면에서 열어도 별도 저장 데이터가 생기지 않는다.
- PDF 이름·페이지 수·원본 파일·필기 데이터의 스키마를 버전 관리한다. 원본 파일은 보관함에 복사하고 외부 파일 경로에 의존하지 않는다.

## 5. PDF 화면과 필기 기능

### 5.1 와이어프레임

```text
[‹] 강의자료.pdf                              [내보내기 ▾]
    내 보관함 / 알고리즘 / 강의

┌────────────────────────────────────────────────────────┐
│ [페이지] │ [선택] [펜 ▾] [형광펜] [지우개]              │
│          │ [도형 ▾] [텍스트]                 [↶] [↷]    │
├──────────┬─────────────────────────────────────────────┤
│ 페이지   │                                             │
│ 미리보기 │                 PDF + 필기                  │
│          │                                             │
├──────────┴─────────────────────────────────────────────┤
│ [검색]       [‹] 2 / 24 [›]      [−] 100% [+] [맞춤 ▾]  │
└────────────────────────────────────────────────────────┘
```

- 페이지 미리보기는 기존 사이드바처럼 슬라이드로 열고 닫는다. 별도의 페이지 관리 모드나 페이지 편집 도구를 추가하지 마.
- 좁은 화면에서는 페이지 미리보기를 접고 도구 모음을 재배치한다. 사용자가 펼치면 콘텐츠를 가리지 않는 드로어 방식을 사용할 수 있다.
- PDF 종이는 원본 색상을 유지한다. 다크 테마에서 PDF 원본 색상을 임의 반전하지 마.
- 제목·내보내기는 기존 LOXT 도구 모음과 크기·간격을 맞춘다. 선택 도구 상태는 접근 가능한 방식으로 구분한다.
- 펜 색상·굵기, 도형 세부 종류는 도구 메뉴에서 표시한다. 모든 옵션을 항상 늘어놓지 않는다.

### 5.2 기능

- PDF 페이지 이동, 페이지 번호 입력, 확대·축소, 너비/페이지 맞춤, 내부 스크롤.
- 텍스트 레이어 선택·복사와 검색·이전/다음 결과 이동.
- 이미지로만 된 PDF는 표시·필기는 가능하지만 OCR 텍스트 검색은 이번에 추가하지 않는다.
- 펜, 반투명 형광펜, 지우개, 직선·화살표·사각형·원, 텍스트 상자.
- 2.0.0 지우개는 추가한 필기 객체/획 단위로 삭제한다. 원본 PDF 내용 삭제·부분 획 절단은 범위 밖이다.
- 선택 도구로 필기 객체 선택·이동·크기 조절·삭제. PDF 원본 텍스트와 LOXT 텍스트 상자 편집을 구분한다.
- 텍스트 상자는 Enter로 줄바꿈, Esc/바깥 클릭으로 편집 종료. 내용은 유지하고 빈 상자는 제거한다.
- 실행 취소·다시 실행, 자동 저장, 저장 중·저장됨·저장 대기·실패 상태.
- 원본 PDF와 필기를 분리하고, 필기는 페이지 좌표로 저장한다. 화면 픽셀 좌표를 영구 데이터로 저장하지 않는다.
- 확대·회전 메타데이터·CropBox·다른 페이지 크기에 맞춰 좌표를 변환한다. 사용자가 페이지 순서를 바꾸거나 원본을 편집하는 기능은 추가하지 않는다.
- 마우스·터치·펜 입력을 처리한다. 그리기와 스크롤·확대를 구분하고, 실제 iPad 검증 없이 Apple Pencil 압력·완벽한 손바닥 거부를 보장한다고 쓰지 마.
- 필기 포함 PDF / 원본 PDF 내보내기. 원본을 덮어쓰지 않고 한글 글꼴·형광펜 투명도·도형·페이지 좌표를 검증한다.
- 필기 포함 내보내기는 시각적 결과를 합친 PDF다. 다른 PDF 앱에서 LOXT 필기가 계속 편집 가능하다고 약속하지 마.
- 손상·암호화·과대 파일·저장 공간 부족은 명확히 안내한다. 암호화 PDF는 2.0.0에서 지원하지 않고 암호 해제 사본을 요청한다. 브라우저/앱이 멈추지 않도록 정리한다.
- PDF에 포함된 스크립트를 실행하지 않는다. 외부 링크는 명시적인 사용자 클릭으로만 열고 파일·네트워크 자동 실행을 막는다.

| 텍스트 도구 → 페이지 클릭 후 입력 | T |

- iPad 외장 키보드의 modifier·브라우저 단축키 동작은 실제 테스트한다. 지원하지 못하는 조합을 검증 완료로 쓰지 않는다.

## 6. 개인 서버와 웹 연결 구조

### 6.1 공통 서비스·연결 계층

- React 화면을 재사용하고 PC용 IPC 어댑터와 웹용 API 어댑터를 분리한다.
- 보관함·메모·PDF·변환 서비스가 공통 검증·저장 규칙을 사용하도록 한다. 웹이 Electron IPC를 직접 호출하는 구조는 금지한다.
- `window.desktop`을 웹에 가짜 객체로 붙이고 성공 상태만 반환하는 식으로 구현하지 마.
- 기능 지원 여부를 capability로 전달한다. 웹에서 불가능한 PC 브라우저 탭·시스템 소리·네이티브 파일 선택 등을 제대로 구분한다.
- REST 등 요청/응답과 인증된 WebSocket 등 상태 이벤트를 사용한다. 프레임마다 전체 보관함을 방송하지 않는다.
- 오디오·PDF는 스트리밍·범위 요청으로 제공한다. 전체 파일을 JSON/base64로 반복 복사하지 않는다.
- 웹 정적 파일·SUIT·PDF worker·필요 리소스는 설치본에 포함한다. 개인 화면 실행 시 CDN을 필수로 하지 않는다.
- 웹 앱 manifest·LOXT 아이콘을 제공하고 지원하는 기기에서는 홈 화면에 추가해 앱처럼 열 수 있게 안내한다. 인증 API·개인 파일을 서비스 워커에 무조건 캐시하지 않는다. 홈 화면 추가가 오프라인 전체 앱·백그라운드 녹음을 보장한다고 쓰지 마.

### 6.2 내 기기 연결 UI

기존 설정 사이드바에 **내 기기 연결** 항목을 추가한다.

```text
내 기기 연결

[ 같은 Wi-Fi에서 연결 허용  켜짐/꺼짐 ]

연결 상태 · PC 이름
접속 주소                         [주소 복사]
[ QR 코드 ]                       [연결 안내]

연결된 기기
아이패드       마지막 연결 시각      [연결 해제]
아이폰         마지막 연결 시각      [연결 해제]
```

- 최초 설치 시 외부 접속은 꺼짐. 사용자가 켜면 설정을 기억하고 이후 앱 실행 중 서버를 자동 시작한다.
- 서버 준비·오류·포트 충돌·사용 가능 주소·네트워크 변경 상태를 표시한다.
- 같은 로컬 네트워크를 대상으로 한다. 인터넷 포트 개방·UPnP·터널·공용 서버를 자동 추가하지 않는다.
- Windows 방화벽은 앱의 필요한 포트·Private 프로필 범위로 안내/설정한다. OS 승인 절차가 필요하면 그대로 안내하고 방화벽을 전체 해제하지 않는다.
- 서버 시작 실패가 PC 앱 시작·녹음·보관함 사용을 막아서는 안 된다.
- 노트북 절전·LOXT 종료·연결 끄기는 연결 종료로 안내한다. 항상 켜진 Windows 서비스나 트레이 상주를 새로 추가하지 않는다.
- 재시작·IP 변경 시 주소/QR/HTTPS 인증서 호스트를 갱신한다. 같은 Wi-Fi라도 AP 격리·게스트망·방화벽 때문에 연결되지 않을 수 있음을 진단 화면에서 안내한다.

### 6.3 기기 승인과 개인 데이터 보호

- 한 PC 설치는 하나의 개인 보관함 호스트다. 여러 승인 기기는 같은 소유자의 클라이언트다. 다중 사용자 조직·역할·협업 계정은 만들지 않는다.
- QR에는 짧은 유효시간·일회용 연결 요청 값만 사용한다. 영구 접근 토큰·인증서 개인키를 넣지 마.
- QR 스캔 후 모바일은 대기 화면, PC는 기기 승인 창을 표시한다. PC 승인 전에는 파일·목록·스크립트가 노출되지 않는다.
- PC에서 기기를 해제하면 해당 인증과 활성 연결이 취소된다. 모든 API·파일 다운로드·이벤트 구독에서 인증을 검사한다.
- HTTPS 세션, CSRF/Origin/Host 검사, 연결 시도 제한, 허용한 로컬 네트워크 바인딩을 설계한다. 모든 인터페이스에 무조건 개방하거나 인증 없이 CORS 전체 허용하지 마.
- 파일 접근은 workspace·항목 ID를 통해 서버가 경로를 계산한다. 사용자 입력의 임의 절대 경로·상위 경로 이동·심볼릭 링크 우회를 거부한다.
- 모바일에서 모델 삭제·라이브 프로세스 제어·임의 쉘 실행·PC 전체 파일 탐색을 제공하지 마.
- 로그·진단·캡처에 세션 토큰·개인키·실제 녹음 내용이 남지 않게 한다.

### 6.4 HTTPS와 초기 기기 설정 — 숨기면 안 되는 조건

- 모바일 브라우저의 마이크 녹음은 신뢰된 보안 컨텍스트가 필요하다. LAN HTTP 주소를 localhost 예외로 취급하지 않는다.
- 공용 도메인·클라우드·인증서 서비스를 몰래 도입하지 마. 기본 설계는 설치별 전용 로컬 인증기관과 서버 인증서, 앱 내 초기 연결 안내다.
- 서버 실행·인증서 생성은 앱이 처리한다. iPhone/iPad의 최초 인증서 설치·신뢰는 OS가 요구하는 사용자 단계이며 웹에서 자동 완료할 수 있다고 주장하지 마.
- 인증서 신뢰의 의미·확인할 PC·기기 제거 방법을 짧게 안내한다. 검증을 끄거나 인증서 오류 무시를 정상 사용 절차로 만들지 마.
- 인증기관 개인키는 PC에만 보관하고 설치별로 다르게 생성한다. 설치 파일에 공통 개인키를 포함하지 않는다.
- 필요한 공개 인증서 배포용 부트스트랩은 인증 전 보관함 데이터가 없는 최소 안내로 제한한다. 실제 저장·파일·인증 세션은 신뢰된 HTTPS에서 처리한다.
- 인증서 호스트·기간·IP 변경·재설치를 고려하고 개인 서버 ID가 바뀌면 다른 PC로 구분한다.
- 실제 Safari에서 신뢰된 연결과 녹음을 검증하지 못하면 이를 완료 항목으로 처리하지 않는다. 어려움이 있으면 별도 외부 서비스를 넣기 전에 구체적인 제약과 대안을 보고한다.

## 7. PC·모바일 동시 수정과 저장 복구

- PC와 웹 모두 같은 서비스의 직렬화·revision 검사를 사용한다. 웹만 검사하고 PC가 무조건 덮어쓰는 구조는 금지한다.
- 항목 ID, 호스트 ID, 스키마 버전, revision, 요청 ID를 사용한다. 저장시간만 비교해서 최신이라고 덮어쓰지 마.
- 요청 재시도는 멱등성을 보장한다. 파일 재업로드·변환 재요청으로 중복 항목·중복 작업이 생기지 않게 한다.
- PDF의 각 필기 객체에는 안정적인 ID를 부여한다. 별개 객체 변경은 안전하게 합칠 수 있지만 같은 객체 충돌은 명시적으로 처리한다.
- 메모 문서의 동시 편집은 오래된 revision을 거절하고 사용자 변경을 임시 사본으로 보존한다. 원격 최신 내용 보기·내 변경 사본 저장 등 선택을 제공한다. 임의 자동 덮어쓰기 금지.
- 변경한 객체가 다른 기기에서 삭제·이동됐다면 안내하고 초안을 보존한다. 저장 재시도가 삭제된 항목을 자동 부활시키지 않게 한다.
- 실행 취소는 해당 클라이언트의 조작을 대상으로 하며 다른 기기의 이후 변경을 조용히 제거하지 않는다. 충돌 시 다시 확인한다.
- 모바일의 연결 끊김·화면 새로고침에서 작성 중 메모·필기를 임시 저장하고 복구한다. 확인된 서버 저장과 로컬 저장 대기를 구분한다.
- 임시 데이터는 호스트·workspace·항목별로 분리한다. 다른 PC에 연결하거나 다른 보관함으로 바꿔도 섞이지 않는다.
- 오프라인 전체 보관함 복제·CRDT 공동 편집·오프라인 전체 앱은 추가하지 않는다. 연결 복구와 현재 편집 초안 보호까지만 제공한다.
- 파일 쓰기는 안전한 임시 파일·원자적 교체, 보관함 변경은 공통 직렬화로 처리한다. 업로드 실패 시 반쪽 항목을 정상 파일처럼 표시하지 않는다.
- 기존 사용자 스키마는 백업·호환 확인 후 비파괴적으로 확장한다. 마이그레이션 실패 시 기존 보관함을 잃지 않도록 한다.

## 8. 모바일 녹음과 PC 변환

- Work에서 모바일 마이크 권한 요청·녹음·일시정지·중단·버리기·업로드·변환 요청을 제공한다.
- 컴퓨터 소리·다른 앱 전체 소리를 모바일 마이크 기능과 혼동하지 않는다.
- PC의 00:00:00 타이머 규칙을 유지하고 일시정지 시간은 제외한다.
- 서버 변환 전에 파일 업로드 상태를 구분한다. 실제 업로드 수치와 실제 대기열 상태를 표시하고 추론 진행률을 임의로 만들지 않는다.
- 모바일 모델 선택은 PC에 설치된 모델을 기준으로 한다. 미설치 모델은 상태와 PC에서 설치할 안내를 제공하고 모바일 요청으로 몰래 다운로드·설치하지 않는다. 설치된 모델의 실행 준비는 기존 엔진 경로를 재사용한다.
- 모바일 녹음도 중단 후 버리기·변환하기 → 폴더·PC 모델 선택 흐름을 따른다.
- 업로드·요청 재시도, 저장 공간 부족, 연결 끊김, 모델 미설치·준비 실패를 처리한다.
- PC에서 이미 진행 중인 작업과 같은 Work 대기열을 사용한다. 웹 요청마다 별도 GPU 모델 프로세스를 무제한 실행하지 않는다.
- 모바일 연결 종료 뒤에도 서버가 수락한 변환은 PC에서 계속된다. 재접속하면 작업 ID로 결과를 찾는다.
- 2.0.0 모바일 녹음은 화면이 열린 전경 사용을 기준으로 한다. iOS 잠금·다른 앱 전환·브라우저 강제 종료 뒤 녹음 지속을 보장하지 마. 중단 감지·현재 데이터 보존·복구를 검증한다.
- 모바일 Live 스트리밍, 모델의 모바일 실행, Live 모델 변경·성능 개편은 이번에 추가하지 않는다.

## 9. 라이브러리 선택·성능

- PDF 렌더링은 PDF.js display 계층을 우선 검토하고 LOXT 전용 UI를 구성한다. 기본 외부 뷰어를 그대로 붙이지 않는다.
- 필기 내보내기는 pdf-lib 등 실제 검증한 라이브러리로 구현한다. 한국어 폰트·벡터 필기·형광펜·원본 페이지 보존을 확인한다.
- 선택 버전의 Node/Electron/Safari 호환성·worker 경로·라이선스를 확인하고 잠금 파일 및 제3자 고지를 갱신한다. 특정 최신 버전을 검증 없이 강제하지 마.
- PDF worker·글꼴·CMap 등 실제 필요한 리소스를 패키지한다. 현재 Electron file 로딩에서 worker 제약이 있으면 로컬 custom protocol 등 안전한 방식을 검증한다.
- 긴 PDF는 보이는 페이지 중심으로 렌더링하고 제한된 캐시·해상도를 사용한다. 모든 페이지를 고해상도 캔버스로 상주시켜 메모리를 소진하지 마.
- 필기는 프레임 단위 저장 대신 획 완료·편집 완료·제한된 묶음 저장을 사용한다. 저장 대기를 닫기 전에 처리한다.
- 네트워크는 전체 보관함 반복 전송 대신 필요한 조회·변경 이벤트를 보낸다. 이벤트 누락·재연결에는 기준 데이터 재조회 경로를 둔다.
- 모델 로딩·기존 GPU 조정을 유지하고 새 서버/PDF 작업이 오디오 처리·UI 반응을 막는지 측정한다.
- 수치 없는 성능 개선·압력 필기 품질·배터리 효율을 사실처럼 주장하지 마.

## 10. 구현 순서

1. 현재 기능·데이터·IPC·스타일·테스트를 확인하고 요구사항별 추적표 작성.
2. U01–U09 수정과 공통 저장·연결 계층 정리. 기존 PC 회귀 검증.
3. PDF 항목·뷰어·필기·저장·내보내기 완성. PC 양 테마·패널 검증.
4. 개인 서버·기기 승인·HTTPS·설정·인증 API 구현.
5. 기존 화면을 웹 어댑터에 연결하고 모바일 반응형·동시 편집 충돌·복구 검증.
6. 모바일 Work 녹음·업로드·PC 변환 요청 구현 및 실제 기기 검증.
7. 2.0.0 Windows 설치 파일·README·릴리스 문구·소개 사이트·샘플 캡처·ZIP 마무리.

중간 단계가 끝났다는 이유로 전체 작업 완료를 선언하지 마. OS 승인·실제 기기 등 사용자가 해야 할 검증만 구체적으로 요청하고 독립적으로 진행 가능한 작업은 계속한다. 어려운 기능을 조용히 제외하거나 샘플 상태로 성공을 대신하지 않는다.

## 11. 검증 및 완료 조건

### 11.1 데이터·기능

- 실제 사용자 데이터 대신 별도 테스트 프로필·예시 파일·여러 독립 호스트를 사용한다.
- 기존 릴리스 회귀 테스트와 의미 있는 신규 단위·통합·앱 UI 검증을 실행한다.
- PDF 불러오기·재실행·이동·이름 변경·휴지통·복구·ZIP·필기 저장·충돌·내보내기를 검사한다.
- PDF 확대/다른 페이지 크기/회전 정보에서 필기 좌표가 동일하게 보이고 내보낸 PDF에서도 일치해야 한다.
- 한글·긴 제목·많은 페이지·이미지 PDF·손상 파일·암호화 파일·과대 업로드·저장 공간 부족을 검사한다.
- PDF 단축키가 다른 탭·메모 입력·텍스트 입력에 침범하지 않아야 한다.
- PC 종료 후 모바일 연결 종료 표시, 서버 재시작 후 재연결, IP 변경, 기기 해제, 만료 QR·재사용 QR을 검사한다.
- 승인 전 목록·파일·작업 정보가 노출되지 않아야 한다. 경로 우회·잘못된 Origin·위조 revision·중복 요청을 검사한다.
- PC와 모바일의 같은 메모/PDF 동시 수정, 항목 삭제 중 저장, 재접속 재시도에서 데이터 손실이 없어야 한다.
- 모바일 업로드는 PC 보관함으로만 들어가고 다른 테스트 호스트와 데이터·인증·초안이 섞이지 않아야 한다.

### 11.2 화면·기기

- Work/Live × 다크/라이트 × PC 창 크기·패널 폭·스크립트/메모 폭을 검사한다.
- 기존 180개 화면 조합의 실패 조건을 회귀 조건으로 사용하고 새 PDF·연결 설정·모바일 상태를 추가한다.
- 390·768·1024·1440px, 모바일 가로/세로, 터치, iPad 외장 키보드에서 주요 조작을 확인한다.
- 실제 Windows DPI와 Electron 확대를 구분해서 기록한다. 실제 iPad/iPhone Safari 결과와 브라우저 에뮬레이션을 구분한다.
- PDF의 페이지 영역 열기·닫기, 펜·지우개·도형·텍스트, 좁은 도구 모음, 모달 전체 차광을 캡처한다.
- 실제 Safari HTTPS·마이크·파일 업로드·PC 변환·결과 재생을 확인한다. 실기기가 없다면 미검증으로 기록하고 완료 주장을 제한한다.
- 테스트 가짜 입력·샘플 스크립트·GPU 추론·실제 필기·실제 네트워크 검증 여부를 각각 명시한다.

### 11.3 측정·보고

- 앱 시작, PDF 첫 페이지·스크롤, 긴 PDF 메모리, 서버 연결·저장 지연, 업로드·PC 대기열 상태 전파를 가능한 범위에서 측정한다.
- 측정 조건·파일 크기·페이지 수·기기·앱 버전·테마를 기록한다. 측정하지 않은 효과는 주장하지 마.
- 기존 조사 ID와 신규 기능별 완료/실패/미검증·관련 테스트·캡처·파일 위치를 추적표로 제출한다.
- 실제 기기·인증서·외부 게시 같은 남은 절차를 명확히 구분한다.

## 14. 설계 점검 결과와 공식 참고

다음 충돌은 위 요구사항에서 해결했다.

| 쟁점 | 최종 결정 |
|---|---|
| 공용 서버인가 개인 서버인가 | 사용자별 PC 개인 서버, 승인된 자기 기기 연결 |
| 웹 화면만 띄우면 완성인가 | React 재사용 + 공통 서비스 + IPC/API 어댑터 필요 |
| 아무 초기 설정도 필요 없는가 | 서버 실행 자동화, 모바일 HTTPS 신뢰는 OS 요구 단계 안내 |
| 중단이 일시정지인가 | 일반 일시정지와 구분한 최종 중단·저장·변환 대기 |
| 내보내기 화살표도 없애는가 | 변환하기만 제거, 내보내기 형식 선택 화살표 유지 |
| PDF 페이지 관리까지 추가하는가 | 페이지 미리보기 열기·닫기, 원본 페이지 편집 제외 |
| PC·모바일 동시 편집은 누가 이기는가 | revision·충돌 처리, 조용한 덮어쓰기 금지 |
| 모바일에서도 Live를 실행하는가 | 저장된 Live 보관함은 제공, 신규 Live 실행은 PC 전용 |
| 모바일 작은 버튼도 PC 크기로 고정하는가 | PC 스타일 유지, 터치 조작 영역은 별도로 확보 |
| PDF는 무조건 검색 가능한가 | 텍스트 PDF만 검색, 이미지 OCR 제외 |

공식 자료 확인일: 2026-10-08. 구현 시 선택한 버전의 문서를 다시 확인한다.

- PDF.js는 렌더링용 display 계층과 viewer 계층을 제공한다. LOXT UI로 구성하고 번들 리소스·환경 호환을 검증한다. [PDF.js Getting Started](https://mozilla.github.io/pdf.js/getting_started/)
- pdf-lib의 페이지 그리기 API는 텍스트와 SVG 경로 등을 제공한다. LOXT의 좌표·폰트·형광펜 품질은 별도 검증 대상이다. [PDFPage API](https://pdf-lib.js.org/docs/api/classes/pdfpage)
- 마이크 접근은 보안 컨텍스트와 사용자 권한을 요구한다. [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)
- 수동 설치한 인증서는 iOS/iPadOS에서 SSL 신뢰를 별도로 켜야 할 수 있다. [Apple 인증서 신뢰 안내](https://support.apple.com/en-au/102390)
